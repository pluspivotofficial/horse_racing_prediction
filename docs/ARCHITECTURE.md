# アーキテクチャ & スコアリング仕様

## 全体像

```
 netkeiba (実データ)
      │  scrape (cached, rate-limited)
      ▼
 engine/netkeiba/parser.py     HTML → 構造化 (Race, Entry, Horse, PastRun)
      │
      ▼
 engine/features.py            11ファクター → Factor(score 0-100, note, sample)
      │
      ▼
 engine/scoring.py             合成能力値 → softmax勝率 → Harville複勝率 → 期待値
      │
      ├─ engine/betting.py     +EV & 分数ケリー → 推奨馬券（精算用の券種・組合せ付き）
      ├─ engine/settlement.py  推奨馬券 × 実配当 → 収支・エクイティカーブ
      └─ engine/commentary.py  7ペルソナ → マルチ視点コメント
      │
      ▼
 engine/pipeline.py            RacePrediction + データ欠損レポート → JSON
      │
      ▼
 web/ (Next.js) / web/showcase (自己完結HTML)   ダッシュボード表示
```

## データ取得（`engine/netkeiba/`）

netkeiba の4エンドポイントで完結（すべて実ページで検証済み）:

| エンドポイント | 用途 |
|---|---|
| `race/top/race_list_sub.html?kaisai_date=YYYYMMDD` | その日のrace_id一覧 |
| `race/race/shutuba.html?race_id=` | 出馬表（枠・馬・騎手・斤量・オッズ） |
| `race/race/oikiri.html?race_id=` | 追い切り（調教評価S〜D＋短評） |
| `db/race/{id}/` | レース条件・天候・馬場・確定結果・払戻（DBは数日遅れ） |
| `race/race/result.html?race_id=` | **レース当日の**着順・確定オッズ・**払戻**（直近レース用） |
| `db/horse/result/{id}/` | 各馬の全出走履歴（適性分析の核） |
| `db/horse/ped/{id}/` | 3代血統表（父・母・母父） |
| `db/horse/sire/{sire_id}/` | 父の産駒成績（芝/ダ別勝率・EI・平均勝ち距離・重賞） |

- **礼儀**: 1リクエストずつ・最小間隔0.8s・記述的User-Agent・全ページをディスクキャッシュ
- **オフライン動作**: 一度取得すればネットワーク不要で再現可能（開発・デモ・テストが安定）
- **エンコーディング**: `db.netkeiba.com`=EUC-JP / `race.netkeiba.com`=UTF-8 を自動判定

`race_id` は `YYYY VV KK DD RR`（年・競馬場・回・日・レース番号）を内包し、場コードから競馬場名を復元できます。

## ファクター設計（`engine/features.py`）

各 `Factor` は **score(0-100, 50=中立)・note(日本語根拠)・sample(該当過去走数)** を返します。
条件別成績（コース・距離・馬場・天候・騎手）は **shrinkage** で総合力へ縮約:

```
score = cond_score × n/(n+k) + base × k/(n+k)     # k=3（クラスはk=2）
```

これにより「函館2戦2連対だから100点」のような小サンプル過剰評価を抑制します。
近走は **recency weight**（半減期4走）で直近を重視。着順は頭数で正規化
（`1 - (着-1)/(頭数-1)`）し、少頭数と多頭数を公平に比較します。

| key | ラベル | 重み | ロジック |
|---|---|---|---|
| `recent_form` | 近走成績 | 0.20 | 直近6走の正規化着順（recency加重）＋上昇/下降トレンド |
| `class_fit` | クラス実績 | 0.14 | 当該格以上での成績・最高着順 |
| `distance_fit` | 距離適性 | 0.10 | ±200m帯の成績 |
| `course_fit` | コース適性 | 0.08 | 同一競馬場の成績 |
| `jockey_fit` | 騎手相性 | 0.08 | その馬×今回騎手のコンビ成績・乗替検出 |
| `workout` | 追い切り | 0.07 | 最終追い切り評価(S〜D)＋短評 |
| `pace_fit` | 脚質決め手 | 0.06 | 通過順→脚質推定＋上がり3F最速 |
| `going_fit` | 馬場状態 | 0.06 | 良/稍/重/不の成績 |
| `surface_fit` | 馬場適性 | 0.05 | 芝/ダの成績 |
| `pedigree` | 血統 | 0.05 | 父産駒の**芝/ダ別勝率・EI・平均勝ち距離**を当日条件と照合＋母父。未経験条件で重み増 |
| `weather_fit` | 天候相性 | 0.04 | 晴曇 vs 雨雪の成績 |
| `condition` | 馬体・調子 | 0.04 | 馬体重増減・使用間隔 |
| `draw_fit` | 枠順 | 0.03 | 距離/馬場に応じた内外の有利不利 |

## 確率化（`engine/scoring.py`）

1. **能力値** = ファクターの重み付き平均（0-100）
2. **勝率** = softmax（temperature=9.5）— 上位馬の勝率が現実的な20-40%帯に収まるよう調整
3. **複勝率(top3)** = Harville近似（1着・2着・3着になる確率をペアワイズに合成）
4. **期待値** = `勝率 × オッズ`、`妙味 = 期待値 - 1`

上位5頭に競馬新聞式の印（◎◯▲△☆）を付与します。

## 馬券推奨（`engine/betting.py`）

2つの思想を併用:

- **バリュー(+EV)**: `勝率 × オッズ > 1` の単勝を、**分数ケリー(1/4)** でサイズ調整
- **的中重視**: ◎軸の複勝・ワイド・馬連、混戦時は3連複フォーメーション

出力は期待値順にソートし上位6点。ステークスは「単位(u)」で表現（実際の金額はユーザーの基準額に依存）。

## コメント生成（`engine/commentary.py`）

同じ数値を **5つの視点** で解釈し、語らせます（該当する視点のみ発話）:

📊 データ分析官 ／ 🐎 展開ラボ ／ 🤝 相性ウォッチャー ／ 💰 妙味ハンター ／ ⚠️ リスク番人

これにより一律の断定ではなく、実際のハンデ検討会のような多声的な解説になります。

## 収支シミュレーション（`engine/settlement.py`）

各推奨馬券には精算用の構造（`pay_key`＝券種、`combos`＝買い目の馬番組合せ）を持たせ、
レース結果ページから取得した **実際の払戻(配当)** で1点ずつ精算します。

* 1点=100円（`unit_yen`）、払戻はnetkeiba方式で100円あたり → 的中時 `払戻/100 × 賭金`
* 複勝・ワイド等の複数当たり目は、配当表に載っているか否かで判定（＝実際の上位2/3着ルールを
  そのまま反映するため、頭数による場合分け不要）
* 週末を1レースずつ進めて資金を更新し、**エクイティカーブ・回収率・的中率・最大ドローダウン・
  券種別ROI** を出力

> 注意: 本シミュレーションは高分散です。1週末では利益が少数レースの的中に偏るため、
> UIでもその旨を明示しています。安定した回収率評価には複数週の集計が必要です（ロードマップ）。

## バックテストの誠実性

デモは過去週末（結果既知）を対象にしますが、**予想のランキングには確定オッズ等の
事後情報を一切使いません**（`want_result` は結果の突合表示にのみ使用）。
したがって「◎複勝率70%・単勝回収率154%」は素の実力評価による成績です。
市場オッズを事前分布として取り込む補正は、ライブ予想時のみ有効化する将来拡張とします
（[WHATS_MISSING.md](WHATS_MISSING.md) 参照）。
